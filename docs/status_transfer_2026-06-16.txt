7. Recommended Nav2 tuning plan

Priority 1: switch controller from DWB to Regulated Pure Pursuit.

Reason:

- Carter-style differential-drive robots in simulated warehouse-like environments often work better with a stable path-tracking controller.
- RPP is commonly used in Nav2 for smoother path following and obstacle-aware speed regulation.

Target file:

- config/nav2_params_custom.yaml

Recommended direction:

- Use:
  nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController
- Keep local costmap at least 5 x 5.
- Tune lookahead distance and speed conservatively.
- Avoid overly aggressive stuck detection during long runs.

Priority 2: tune AMCL.

Recommended direction:

- Increase particles if localization is unstable.
- Check initial pose is set correctly before each run.
- Monitor AMCL pose against /chassis/odom during long tasks.
- Abort or reset when AMCL/odom disagreement grows too large.

Priority 3: tune costmaps and inflation.

Recommended direction:

- Verify robot_radius or footprint matches Carter robot size.
- Use smoother inflation instead of hard narrow obstacle margins.
- Ensure local costmap is large enough for long-distance recovery behavior.

Priority 4: run targeted health tests before full evaluation.

Recommended sequence:

1. Reset robot to origin in Isaac Sim.
2. Verify /chassis/odom is near (0, 0).
3. Start /scan bridge.
4. Start static TF base_link -> base_footprint.
5. Start Nav2 with config/nav2_params_custom.yaml.
6. Set AMCL initial pose.
7. Start vln_nav2_bridge.
8. Run targeted health test.
9. Only run full 15-trial evaluation if targeted health is stable.
