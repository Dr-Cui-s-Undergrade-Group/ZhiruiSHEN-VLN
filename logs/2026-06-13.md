## Node 6 Trial 6-11 重跑尝试

启动 `vln_nav2_bridge` 后确认：

- `/front_stereo_camera/left/image_raw` 为 `sensor_msgs/msg/Image`，约 2.6 到 3.1 Hz。
- Qwen server GPU 后端启动成功。
- `/vln_instruction`、`/vln_goal_pose`、`/vln_trial_result` 均存在。

第一次重跑前，Isaac 机器人已经在 shelf 区域附近，不能再按原点调用 `/set_initial_pose`。按原点初始化 AMCL 后，Nav2 认为机器人在原点，但 `/chassis/odom` 显示实际目标距离约 13 m；该轮已取消。

按当前 odom 重新初始化 AMCL 后，Trial 1 从 shelf 区域反跑 chair。视觉扫描第 6 次识别到 chair，并解析到：

```text
chair -> (-0.54, -0.69, yaw=1.57)
parse_method=visual_semantic_map
```

但机器人经过 recovery 后停在货架边缘，预检变为：

```text
[BLOCKED] current_odom:/chassis/odom: world=(-6.762, 10.778, yaw=0.360)
free=92.0%, occupied=7.1%, unknown=0.9%
nearest_free ~= (-6.726, 10.814)
```

此时：

- 当前起点到 `chair (-0.54, -0.69)` 的 `compute_path_to_pose` 失败。
- 显式使用 `nearest_free`、`shelf/package_area` 或 `(-6.20, 10.60)` 作为 start 时，到 chair 的 planner 均成功。
- 手动用短 `/cmd_vel` 脱离到 `(-6.38, 10.80)` 后，`node6_map_preflight` 恢复 `[OK]`，到 chair 的 planner 成功。

第三次重跑时，Trial 1 从约 `(-6.01, 10.84)` 开始。视觉扫描 8 次都没有看到 chair/plant，随后使用 semantic candidate：

```text
Target was not confirmed in the current view.
Navigating to semantic candidate 'chair': x=-0.54, y=-0.69, yaw=1.57
```

这次 Nav2 没有再出现 `GridBased` 失败，开始沿全局路径移动，距离从约 12.8 m 逐步下降到约 9.4 m。由于仿真速度偏慢，默认 bridge `nav_timeout_sec=240` 不足以完成 shelf -> chair 的长距离反跑；该轮在超时前主动取消，避免把 timeout 误记为目标/规划失败。

### 当前结论

- AMCL/TF 启动链路已修复。
- chair/shelf 默认语义目标仍然是可规划 free-space 目标。
- 新 blocker 是 shelf 区域末端容差和长距离超时：
  - shelf goal checker 会允许机器人停在货架边缘低 free-ratio 区域；
  - 从该位置反跑 chair 可能因起点贴障碍导致 `GridBased` 失败；
  - 从干净起点反跑 chair 可规划，但默认 240 秒超时过短。

下一轮建议：

1. 重跑 Trial 6-11 前先运行 `node6_map_preflight`，必须确认当前位姿 `[OK]` 且 free ratio 接近 100%。
2. 如果当前位置在 shelf 边缘，先移动到 `(-6.38, 10.80)` 附近或 preflight 给出的 nearest free 候选。
3. bridge 启动时使用 `nav_timeout_sec:=900.0`，auto trials 使用 `--timeout-sec 900.0`。
4. 完成后再把 shelf 目标或 goal checker 容差收紧，避免后续停在货架边缘。

### 结论

- AMCL/TF 和 Nav2 执行链路本轮可用；6 条指令的最终位姿全部进入目标成功半径。
- Bridge 层成功率只有 2/6，是因为后 4 条 shelf/right-shelf 指令在到达后进行视觉确认时，模型多次看到 cart / purple boxes，但判断“shelf 不可见”，最后返回 `semantic_explore_confirm_failed: target_not_visible_after_visual_scan`。
- 这不应再归类为 Nav2 planner blocker。更准确的分类是视觉确认/语义别名问题：真实目标区域到达了，但确认逻辑过度依赖 “shelf” 字面可见，而没有接受 “cart with purple boxes / purple packages / package area” 作为同一语义目标的可确认证据。
- Node 7 的首个优化点应从本轮结果中提取：修复 shelf/right-shelf 的确认语义，或把 bridge 结果拆成 `navigation_arrived` 与 `visual_confirmed` 两个独立指标。
