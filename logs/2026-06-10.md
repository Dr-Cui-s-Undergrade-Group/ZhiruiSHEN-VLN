## Node 5 图像识别链路优化
- 发现问题：原 Node 5 默认只读取 `data/test_samples/warehouse_photo1.png` 静态截图，不会自动读取 Isaac Sim 当前相机画面。因此仿真视角、物体位置或光照变化后，模型仍可能在看旧图，容易误判。
- 当前模型状态：
  - 本地模型：`/home/bluepoisons/Desktop/FURP/VLN/models/Qwen3-VL-2B-Instruct`
  - 模型目录大小约 `4.0G`
  - 当前机器 GPU：RTX 3060 12GB
  - 检查时显存状态：总显存约 12GB，已用约 3.5GB，可用约 8.5GB
  - 结论：当前硬件可以优先尝试 GPU 4-bit 推理，不需要默认强制 CPU；CPU 更适合作为兼容兜底。
- 代码优化：
  - `vln_node_local.py` 新增 `image_topic` 和 `compressed_image_topic` 参数，支持订阅实时 `sensor_msgs/Image` 或 `sensor_msgs/CompressedImage`，并保存为 `data/runtime/latest_camera.png` 供本地 Qwen 推理使用。
  - `run_inference_cli.py` 和 `qwen_model_wrapper.py` 统一改成只解码模型新生成内容，避免把 prompt 也混进输出。
  - prompt 改为要求模型返回紧凑 JSON：`target, visible, confidence, x, y, yaw`，便于后续做 Node 6 定量统计。
  - `text_to_pose_converter.py` 改为优先解析模型 JSON，只有没有 JSON 时才使用关键词坐标兜底。日志中 `method=json` 才代表模型输出真正参与了目标解析。
  - `force_cpu` 改为可配置项，12GB 显存机器上优先尝试 GPU 4-bit 推理，CPU 仅作为兼容兜底。
  - `package.xml` 增加 `sensor_msgs` 依赖。
  - `vln_nav2_bridge_local.launch.py` 增加 `image_topic`、`compressed_image_topic`、`require_fresh_image` 和 `force_cpu` 启动参数。
- 验证：

  - ROS `Image(rgb8/bgr8)` 到 PIL RGB 的解码小测试通过。

### 新版 Node 5 启动方式

基础启动仍然可用，不传相机 topic 时会继续使用静态样例图：

```bash
source /opt/ros/humble/setup.bash
cd /home/bluepoisons/Desktop/FURP/VLN/ZhiruiSHEN-VLN
source install/setup.bash
ros2 run vln_nav2_bridge vln_node_local --ros-args -p use_sim_time:=True
```

接入 Isaac 实时相机后，推荐使用 launch 参数启动：

```bash
source /opt/ros/humble/setup.bash
cd /home/bluepoisons/Desktop/FURP/VLN/ZhiruiSHEN-VLN
source install/setup.bash
ros2 launch vln_nav2_bridge vln_nav2_bridge_local.launch.py \
  image_topic:=/YOUR_CAMERA_IMAGE_TOPIC \
  require_fresh_image:=true \
  force_cpu:=false
```

如果 Isaac 发布的是压缩图像，则使用：

```bash
ros2 launch vln_nav2_bridge vln_nav2_bridge_local.launch.py \
  compressed_image_topic:=/YOUR_COMPRESSED_IMAGE_TOPIC \
  require_fresh_image:=true \
  force_cpu:=false
```

查找 Isaac 相机 topic：

```bash
ros2 topic list | rg 'image|rgb|camera'
```

### 当前判断

- Node 5 之前的“识别差”主要不是 Qwen3-VL-2B 完全不可用，而是视觉输入链路没有接实时相机。
- 现在静态图上模型能按要求输出结构化 JSON，说明后续重点应该放在实时相机、视角质量、目标可见性和评估指标上。
- 后续 Node 6 评估时不要只看导航成功率，还要记录：
  - `visible`
  - `confidence`
  - `method=json` 或 `method=instruction_fallback`
  - 模型目标名称是否正确
  - 最终坐标是否来自模型 JSON 还是规则兜底

### 后续优化方向

1. 在 Isaac Sim 中给机器人加 RGB Camera，并通过 ROS2 Camera Helper 发布实时 RGB 图像。
2. 先用 `require_fresh_image:=true` 强制检查实时图像是否真的进入 Node 5，避免静态图兜底掩盖问题。
3. 为 Node 6 准备 15 组语言指令，按 `plant/chair/purple boxes/shelf/unknown target` 分类统计。
4. 如果实时图像里小目标识别仍差，优先增加开放词表检测前端，例如 GroundingDINO 或 YOLO-World，再把检测框/类别交给 Qwen 做语言到地图目标解析。
5. 2B 模型继续作为在线主模型；后续可以把 8B/更大模型作为离线复核或关键帧二次判读，不建议一开始直接替换在线主链路。
