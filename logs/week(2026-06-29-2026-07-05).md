# 2026-06-29 至 2026-07-05 周报

## 本周主题

本周工作重点从 Node 8 的长距离 AMCL 调参，转向更符合 VLN-CE 的连续导航实验框架。组会反馈指出，当前项目不应继续把“原地 360 度转圈识别”和视觉命中后的推测式 AMCL 重锚作为主线方法，而应让语言模块负责 instruction grounding / semantic goal selection，让 Nav2 负责连续环境中的定位、规划、控制、恢复和到达状态。

新的主线定义为：

```text
instruction -> semantic goal / waypoint candidates -> Nav2 execution -> RViz/debug logs -> continuous-navigation metrics
```

视觉扫描、active search、visual-anchor AMCL reanchor 后续仍可保留为 diagnostic 或 ablation，但不再作为 primary method 来叙述。

## 文献与开源仓库对齐

本周重点阅读和对齐的资料：

- VLN-CE repository: https://github.com/jacobkrantz/VLN-CE
- VLN-CE paper: Krantz et al., "Beyond the Nav-Graph: Vision-and-Language Navigation in Continuous Environments", ECCV 2020, https://arxiv.org/abs/2004.02857
- VLN-CE waypoint paper: "Waypoint Models for Instruction-guided Navigation in Continuous Environments", https://arxiv.org/abs/2110.02207
- NeuPAN repository: https://github.com/hanruihua/NeuPAN

VLN-CE 的关键启发是：连续环境导航不能依赖离散图节点、oracle short-range navigation 或 perfect localization。映射到本项目后，后续实验应主动暴露 Nav2/RViz 中的真实失败类型，包括 global planning failure、local controller stuck、costmap obstacle、AMCL drift、timeout 和 arrival error。

NeuPAN 的定位更接近 local planner / controller，对本项目的价值在于未来作为局部运动规划或避障对照实验。当前阶段不适合直接用 NeuPAN 替换 Nav2 主线，优先级仍是把 Nav2 作为主导航执行层跑清楚。

## 架构调整结论

本周确定的后续技术路线：

1. 保留 Nav2 作为主线执行层。
2. 将 VLN bridge 的主职责收敛为 language grounding、semantic target selection 和 waypoint candidate generation。
3. 不再把原地视觉扫描作为主要成功来源。
4. 不再把 visual-anchor AMCL reanchor 作为主线定位能力。
5. 使用 RViz 和 CSV 日志解释 Nav2 的真实连续导航行为。
6. 评估指标改为 VLN-CE-style continuous metrics。

建议后续 CSV 至少保留：

- trajectory length / TL；
- final navigation error / NE；
- physical arrival within radius / SR；
- SPL-style efficiency；
- timeout / stuck；
- recovery count；
- AMCL vs raw odom disagreement；
- Nav2 action result；
- final pose source。

历史 strict visual task success 可以继续保留，但应作为 visual confirmation ablation，而不是唯一主指标。

## 当前问题与优化空间

### 1. Observation Pose 不应是单点硬编码

当前 `TextToPoseConverter` 对 plant/chair/shelf_package_area 使用固定 observation pose。实验已经证明 chair 的固定观察点不可靠。下一步应改为每个语义目标维护多个 candidate observation poses：

```text
chair:
  object_center: (-0.54, -0.69, 1.57)
  candidate observation poses:
    (-0.20, -1.30, 1.57)
    (0.45, -1.20, 2.50)
    (-0.90, -1.10, 0.80)
    (0.20, -0.69, 3.14)  # current weak candidate, keep as ablation
```

候选筛选顺序建议：

1. 静态 occupancy map 安全检查；
2. Nav2 global path 是否可生成；
3. path length / clearance / local costmap 风险；
4. 到目标物体的 yaw 是否合理；
5. 在线执行后的 final navigation error。

### 2. 长距离任务应优先使用 Nav2 多航点能力

当前 runner 的 `waypoint_sequence` 已经表达了中间航点。2026-07-06 后续补充中已增加 `--waypoint-execution-mode`：默认 `sequential` 仍逐个发送 `goToPose()`，`through_poses` 则使用 Nav2 `goThroughPoses()` 一次性交给 Nav2 路线执行逻辑，更贴近 Nav2 原生路线行为。

### 3. 指标字段还需要补强

当前 CSV 已有：

- `trajectory_length_m`
- `final_navigation_error_m`
- `physical_arrival`
- `cmd_vel_nav_*`

- `goal_safe`

截至 2026-07-02 仍需补：

- AMCL pose；
- raw odom pose；
- AMCL/raw odom disagreement；
- SPL-style efficiency；
- recovery count；
- waypoint-level status；
- global path length if available。

2026-07-06 后续补充已经完成 AMCL pose、AMCL/raw odom disagreement、route planner result、global path length、SPL-style efficiency、recovery count 和 waypoint-level status 字段；这些在线指标仍需要 Isaac/Nav2 运行后用真实 feedback 验证。

### 4. Nav2 成功条件应单独报告

当前 Nav2 参数中 `xy_goal_tolerance=0.35`，smoke test 证明 Nav2 action success 可能早于严格 physical arrival。因此后续报告中必须同时写：

- `Nav2 action result`
- `physical_arrival` with explicit radius
- `final_navigation_error_m`

如果要做严格实验，可另建 strict 参数文件，将 `xy_goal_tolerance` 调到 `0.15-0.20 m`，但低负载配置仍可用于保持 Isaac Sim 稳定。
