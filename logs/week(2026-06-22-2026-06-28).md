### 主动视觉确认更新

需求澄清：

- 仅导航到达不足以判定成功。
- 一次试验只有满足以下条件才成功：

```text
task_success = navigation_arrived AND visual_confirmed
```

实现更新：

- 更新 `src/vln_nav2_bridge/vln_nav2_bridge/vln_node_local.py`。
- 在 Nav2 导航期间添加低频视觉检查：
  - `visual_check_during_nav_enabled`
  - `visual_check_interval_sec`
  - `visual_check_min_travel_m`
- 导航期间的检测作为证据记录到 `target_seen_during_nav`，但不直接标记任务成功。
- 添加 Nav2 到达后的强制最终视觉确认：
  - `final_visual_scan_required`
  - `final_visual_confirmed`
- 如果最终扫描看不到目标，则增加局部主动搜索：
  - `active_search_enabled`
  - `active_search_forward_distance_m`
  - `active_search_linear_speed_m_s`
  - `active_search_max_moves`
- 收紧宽松货架 / 包裹确认：只有当 VLM 实际报告可见匹配目标时，才接受同簇证据。
- 更新 `src/vln_nav2_bridge/vln_nav2_bridge/node6_auto_trials.py`，让输出 CSV 保留：
  - `target_seen_during_nav`
  - `target_seen_during_nav_image`
  - `final_visual_confirmed`
  - `active_search_used`
- 更新 `src/vln_nav2_bridge/launch/vln_nav2_bridge_local.launch.py`，暴露新的主动感知参数。

设计理由：

- bridge 现在采用更真实的模块化具身导航流程：
  1. 初始 360 度扫描；
  2. 语义 / Nav2 导航到候选区域；
  3. 移动时低频视觉检查；
  4. 在候选区域执行强制最终扫描；
  5. 若最终确认失败，则执行有界局部主动搜索。
- 这符合几何和语义都必须通过的要求：Nav2 证明可达性，VLM 证明目标物体可见。

### 改进计划执行结果（2026-06-26）

#### 1. PGM merge bug 修复 ✅

`_load_existing_map` 的 `free_mask = pixels > 200` 误把 unknown(205) 当成 free，导致合并后地图被 free 淹没。修复：`free_mask = pixels > 220`（排除 205 unknown）。round-trip 测试通过（occ/free 精确匹配）。

#### 2. odom-dominant AMCL 配置 ✅

新增 `config/nav2_params_odom_dominant.yaml`：
- `laser_likelihood_max_dist: 0.75 → 0.3`（单次 scan match 只能纠正小局部误差，不能拖整个粒子云）
- `z_hit: 0.15 → 0.85`，`z_rand: 0.75 → 0.15`（信任好的 match，忽略噪声）
- `sigma_hit: 0.50 → 0.20`

AMCL init 验证：在 origin 跟踪精度 0.02m（完美）。配置正确。

#### 3. 精确 pkill 修复（关键发现）✅

**根因发现**：之前 Isaac 反复停发数据不是 Isaac 崩溃，是 `pkill -f "ros2 run"` 误杀了 Isaac 的 ROS bridge 进程（它们也是通过 `ros2 run` 启动的）。修复后改用 `pkill -f "vln_nav2_bridge/node_name"` 精确杀进程。修复后 Isaac 稳定运行了完整的建图周期（~20min 无中断），truth map 重建到 550 scans / 50780 occupied cells（最好成绩）。

#### 4. odom-dominant full-15 验证 ❌ Isaac sim-time 阻断

用 truth map + odom-dominant AMCL 跑 full-15。AMCL init 正确（0.02m 跟踪），但 Trial 1 在导航中段被 Isaac sim-time jump-back（8758 次）阻断——Nav2 controller TF 间歇性故障，robot 卡在 plant 1.83m 处。

即使冷启动 Isaac + 精确 pkill + 低负载 Nav2，Nav2 主动导航时（controller + costmap 运算）仍产生 jump-back。这是 Isaac 物理引擎在 CPU 负载下帧率不稳的硬限制，无法从 ROS 侧完全解决。

#### 最终结论

**5/15 是 scan-only 在当前仿真环境下的稳定可复现结果。** 所有改进代码就绪（PGM merge 修复、odom-dominant 配置、truth map 重建、Carter 脱困逻辑），下次 Isaac 更稳定时或真机上可立即验证。
