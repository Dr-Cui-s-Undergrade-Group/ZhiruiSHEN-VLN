# 2026-07-06 - Nav2 / RViz / 3D Lidar 调研与可视化链路整理

## 今日目标

根据 Nav2 官方仓库、RViz 默认配置、`pointcloud_to_laserscan`、STVL，以及 VLFM / VLMaps / VLN-CE / GOAT-Bench 等 VLN/ObjectNav 项目，确定当前仓库最合适的 Nav2 与 RViz 使用方式，并解决 RViz 中雷达和轨迹显示不稳定的问题。

## 阅读资料结论

- Nav2 官方 `nav2_bringup` 是模板，实际项目应维护自己的 bringup/rviz 配置。
- 官方 RViz 默认以 `map` 为 fixed frame，同时显示 map、scan、path、costmap、TF、footprint。
- `pointcloud_to_laserscan` 的职责是把 3D `PointCloud2` 投影为 2D `LaserScan`；在本项目里 `/scan` 应被视为 Nav2/AMCL 的二维投影或调试输入，不适合代表完整 3D 雷达显示。
- STVL / VoxelLayer 是 3D 点云进入 costmap 的进阶方向，但当前应先稳定 2D scan + AMCL + local costmap，再做 3D costmap ablation。
- VLFM / VLN-CE / GOAT-Bench 的方向支持“语言视觉负责语义目标和候选点，几何导航由底层导航系统执行”的分层架构。

## 当前判断

当前最合适的方法是：

- 完整 3D 雷达用于 RViz：`/front_3d_lidar/map_points`
- 2D `/scan` 用于 Nav2/AMCL/local costmap
- RViz fixed frame 固定为 `map`
- RViz 与辅助节点使用 `use_sim_time:=true`
- VLN/VLM 负责语义目标和候选 observation pose
- Nav2 负责定位、规划、控制和恢复
- 实验指标拆开记录：physical arrival、visual confirmation、SPL、trajectory length、AMCL/odom disagreement

这比“只显示 `/scan`”更合理，因为 `/scan` 本质上是导航用二维投影，不是完整雷达。
